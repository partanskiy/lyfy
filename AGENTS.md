# Project instructions

- Read ARCHITECTURE.md first and enforce its layer boundaries.
- Keep exactly two workspace packages: lyfy (library) and lyfy-cli (binary lyfy).
- Only lyfy-cli depends on lyfy. Inputs own launch defaults, CLI, ENV and TOML loading; lyfy owns typed settings and validation.
- Keep exactly four independent managers: lint, fmt, save, apply.
- Managers must never import or invoke one another; share named services.
- Do not add an outputs layer or a fifth command without an architecture discussion.
- Target Arch Linux only. Never mutate the developer's host during tests.
- Keep main protected; use topic branches and pull requests, rebase merge only.
- Use small Conventional Commits. No merge, fixup, squash, amend or release-only exceptions.
- A commit changes at most 300 lines and 12 files, excluding generated Cargo.lock.
- Releases tag existing main commits. Never require a dedicated release commit.
- Versions use YY.M.PATCH calendar numbering like synchrogit, without month/patch padding. Tags remain independent of Cargo's development version.
- The user authorizes merging green PRs by rebase and publishing releases without another approval.
- Release only for Arch Linux x86_64 (amd64). The current distribution target is AUR package lyfy.
- AUR builds must not invoke Python or require it as a make dependency. Ship pre-generated notices in release source archives and static man pages in packages.
- Use pkgname/pkgver variables in PKGBUILD paths and source URLs.
- Own source license: MIT. The user explicitly approved GPL dependencies and GPL terms for linked builds on 2026-10-28. Combined binaries with alpm bindings/libalpm follow GPL-3.0-only; preserve source MIT and ship corresponding dependency sources and notices.
- The user explicitly authorizes the existing AUR credential in the lyfy GitHub Actions secret for automatic AUR publication. Never expose its contents.
- All configuration fields need a snake_case flag and LYFY_UPPER_CASE environment variable.
- Preserve flag > environment > TOML > default precedence.
- Store concrete files and host overlays. Do not introduce configuration templates.
- Keep secrets out of fixtures, output, Git and documentation.
- Use ASCII punctuation in prose and comments.
- Run architecture checks, rustfmt, clippy, library and CLI tests, release build and commit validation before opening a PR.
